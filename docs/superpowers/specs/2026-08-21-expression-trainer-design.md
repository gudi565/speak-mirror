# 实时表达训练系统 — 设计文档

日期：2026-08-21
状态：已确认（用户已批准设计方向）

## 1. 背景与目标

用户（自媒体创作者）在口头表达中存在口头禅过多、词汇笼统、结构松散等问题，希望有一个可以在说话时**实时反馈**的表达训练工具，并在练习结束后生成结构化的分析报告。

参考产品的核心洞察：约 90% 的实时反馈功能（口头禅标红、重复检测、词汇替换、情感分析）由本地规则完成，零延迟零成本；只有会话结束后的报告才真正调用 LLM。本设计遵循同样的混合架构。

**目标：**

- 说话时实时显示字幕、标红口头禅、给出表达反馈
- 练习结束一键生成结构化分析报告（调用用户自带 API Key 的 LLM）
- 报告与逐字稿可导出为 Markdown（Obsidian 友好）
- 实时分析完全离线可用；仅报告生成需要联网

**非目标（v2 及以后）：**

- LLM 增强的实时规则（前后矛盾、立场模糊、金句捕捉、主题跑偏）
- 多用户、云同步、账号体系
- 移动端

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 应用壳 | Tauri (Rust) | 安装包小（几十 MB），音频采集与本地推理在原生侧延迟最低 |
| 前端 | React + TypeScript + Tailwind | 三栏实时 UI，生态成熟（用户已确认） |
| 流式 ASR | sherpa-onnx + 中文流式 Paraformer | Rust 绑定成熟，中文流式识别效果好，模型约 500MB-1GB |
| VAD | sherpa-onnx 内置 silero-vad | 与 ASR 同库，减少依赖 |
| 音频采集 | cpal (Rust) | 跨平台音频输入 |
| LLM 调用 | OpenAI 兼容 HTTP 接口，默认 DeepSeek | 用户自带 Key，流式返回 |
| 情感词库 | 内置小型自维护词表（MVP）；DUTIR 情感词汇本体作为可选下载项 | DUTIR 为大连理工学术资源，需遵守学术授权，不直接打包 |

## 3. 整体架构

三层结构，边界清晰：

```
┌─────────────────────────────────────────────┐
│ 前端 (React)                                 │
│  实时字幕 │ 表达分析面板 │ 反馈卡片流 │ 报告页 │
└──────────────▲───────────────────┬──────────┘
       events  │                   │ commands
  (partial_transcript / sentence_final /       │
   analysis_update / report_chunk)             │
┌──────────────┴───────────────────▼──────────┐
│ Rust 后端                                    │
│  音频采集(cpal) → VAD → ASR(sherpa-onnx)     │
│       → 句子流 → 规则引擎 → FeedbackEvent[]   │
│  SessionState（句子 + 累计统计）              │
│  报告生成（拼 prompt → LLM API → 流式返回）   │
│  设置 / 历史会话 / 文件导出                  │
└─────────────────────────────────────────────┘
```

**通信方式：**

- Rust → 前端：Tauri event 流
  - `partial_transcript`：识别中的临时文本（灰字，可改写）
  - `sentence_final`：句末定稿（含时间戳）
  - `analysis_update`：规则引擎产出的反馈事件与统计更新
  - `report_chunk`：报告生成的流式文本块
- 前端 → Rust：Tauri commands
  - `start_session` / `stop_session`
  - `generate_report`
  - `get_session_snapshot`（前端重连/刷新后拉取快照）
  - `save_settings` / `load_settings`
  - `export_markdown(kind: report | transcript)`
  - `download_models`（模型与词库按需下载）

**会话状态由 Rust 侧持有**：全部句子、累计统计、规则状态都在 `SessionState` 中，前端只是渲染层，刷新或崩溃重连不丢数据。

## 4. 数据流（一次练习的生命周期）

1. 用户点击开始 → Rust 打开音频流，VAD 切分语音段，Paraformer 流式识别；先出 partial（前端灰字），VAD 判停或标点定稿后出 final 句子
2. 每条 final 句子进入规则引擎管线：句子清洗 → 逐条规则执行 → 产出 `FeedbackEvent[]` → 通过 `analysis_update` 事件推给前端
3. `SessionState` 累计句子与统计（填充词计数、语速、情感分布等）
4. 用户点击结束 → 停止采集 → Rust 汇总逐字稿 + 统计 JSON，拼报告 prompt，POST 到配置的 OpenAI 兼容端点，流式返回渲染
5. 报告与逐字稿可一键复制或保存为 Markdown

## 5. 本地规则引擎（MVP 范围）

每条规则是独立模块，统一接口：

```rust
trait Rule {
    fn on_sentence(&mut self, sentence: &Sentence, ctx: &SessionContext) -> Vec<FeedbackEvent>;
}
```

MVP 实现 6 条规则：

| 规则 | 说明 | 触发输出 |
|---|---|---|
| `filler_words` | 口头禅/填充词检测。词表可配置，默认：然后、就是、那个、呃、嗯、其实、比如说 | 字幕中标红；计数；次/分钟频率；高频时提醒 |
| `word_precision` | 笼统词替换建议。内置替换词典，如 想→渴望/期待/向往，很多→大量/海量/充裕，厉害→强大/高效 | 右栏提示可替换词 |
| `repetition` | 滑动窗口（最近 20 句）内 n-gram 相似度 > 0.7 判定为重复 | "这句说过了"提醒 |
| `conclusion_missing` | 连续 5 句描述性内容且无结论标记词（所以、总之、我的观点是、结论是） | 提醒"该给结论了" |
| `example_missing` | 连续输出观点句（含"我觉得/我认为/应该"）且无举例标记（比如、举个例子、就像）超过 4 句 | 提醒"举个例子会更有画面感" |
| `emotion_lexicon` | 情感词标注与七类情感（喜怒哀惧恶惊+其他）分布统计 | 面板展示情感分布，供报告使用 |

**v2 候选**（本设计不实现）：LLM 节流调用规则——前后矛盾、立场模糊、金句捕捉、主题跑偏。

## 6. 报告生成

- 输入：逐字稿全文 + 本地统计 JSON（时长、字数、语速、填充词计数与频率、情感分布、各规则触发记录）
- 内置报告 prompt 模板（约百行），要求 LLM 输出固定七部分结构：
  1. 总评（评分 + 一句话定位）
  2. 亮点分析
  3. 逐句精简（有问题的句子 → 更干练的版本 + 原因）
  4. 词汇替换表
  5. 行为模式分析（填充词触发场景、回避/犹豫模式）
  6. 说服力结构（钩子/观点/论据/CTA）
  7. 下次练习重点
- 要求 LLM 返回 JSON；前端做 schema 校验，解析失败时降级为纯文本渲染并保留原文查看

## 7. 数据与配置

| 项 | 存储 | 说明 |
|---|---|---|
| ASR 模型 | `%APPDATA%/express-trainer/models/` | 首次启动走下载管理器（进度条 + 断点续传） |
| 填充词表 / 替换词典 | 打包进安装包 | 用户可在设置中编辑填充词表 |
| 小型情感词表 | 打包进安装包 | MVP 默认使用 |
| DUTIR 词库 | 可选下载 | 学术授权提示后下载 |
| 设置 | `settings.json`（API Key 存 OS keychain） | base_url、model、口头禅词表等 |
| 历史会话 | `%APPDATA%/express-trainer/sessions/*.json` | 逐字稿 + 统计 + 报告，可回看 |

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| 无麦克风权限/无设备 | 开始页明确提示，不允许进入会话 |
| ASR 模型缺失/损坏 | 启动检测，引导重新下载 |
| API Key 无效 / 网络失败 | 报告区显示错误 + 重试按钮；逐字稿与本地统计不丢失 |
| LLM 返回非预期 JSON | 降级纯文本渲染，可查看原始返回 |
| ASR 识别置信度过低 | 该句标记低置信，不参与规则判定 |

## 9. 测试策略

- **Rust 规则引擎**：单元测试为主。每条规则喂固定句子序列，断言输出事件。这是逻辑最密的部分，覆盖率要求最高
- **文本管线**：合成句子流（mock ASR 输出）做集成测试，验证事件流与统计正确性
- **前端**：组件级测试报告渲染、反馈卡片流、设置表单；Tauri command 层做契约测试
- **报告 prompt**：固定输入快照 + JSON schema 校验测试（用 recorded LLM 响应）

## 10. 里程碑

1. **M1 技术验证**：音频采集 + VAD + 流式 ASR + 字幕显示跑通（最大技术风险，优先验证）
2. **M2 规则引擎**：6 条本地规则 + 三栏 UI 联动
3. **M3 报告与导出**：LLM 报告生成 + Markdown 导出 + 设置页
4. **M4 发布打磨**：打包、模型下载管理器、历史会话回看、Windows 安装包

目标平台：Windows 优先，架构上不阻塞 macOS/Linux。
